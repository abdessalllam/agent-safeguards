# Changelog

## 0.1.0

First release.

- safe-tool: blocks commands that print identity or credential data, withholds output that contains it, and provides `git identity`, `git commit`, and `status coderabbit`. It looks through variable prefixes, shell keywords and wrappers, checks every line of a multi-line command, catches relative credential paths, and judges Git log formats by the last format option.
- delete-guard: blocks recursive deletes outside the current repository and temp folders, plus disk-erase commands (`mkfs.*`, `newfs_*`, `dd` onto a device). It refuses glob-plus-`..` targets, understands wrapper and `xargs` options, and does not trust a `cd` it cannot follow.
- Both hooks block on unreadable or oversized input and on internal errors, and the launcher blocks when the tool crashes.
- When `rtk proxy` is the only reason a command is refused, the refusal now says so and names the fix. Both tools re-run themselves in isolated Python mode when started directly.
- Output scanning is a single detector (`lib/agent_safeguards/secret_scan.py`) that favours false positives: token shapes for common providers, labelled values (`password`, `secret`, `token`, `api_key`, ...), and unlabelled high-entropy strings. Well-known secret file names are refused before the command runs. `rtk proxy` also allows `nl`, `sort`, and `uniq`.
- safe-tool refuses the printing forms of `alias`, `type`, `whence`, `where`, `functions`, `declare`/`typeset` (`-f`, `-F`, `-p`), `export`, `readonly` and bare `set`, and withholds output that shows an alias or function definition, so an alias that hides a host, a key path or a password is not read back to the agent.
- safe-tool refuses commands that read shell startup and history files (`.zshrc`, `.bashrc`, `.profile`, `.zsh_history` and similar) while still allowing `source` and metadata checks, and adds `safe-tool has-key NAME`, which prints `NAME=pass` or `NAME=fail` and never the value.
- safe-tool withholds output that shows a private network address (IPv4 private, link-local and shared ranges, IPv6 link-local, unique-local and global), except the Android emulator's fixed addresses. `AGENT_SAFEGUARDS_SHOW_ADDRESSES=1` turns it off.
- safe-tool also expands globs and braces when it looks for startup-file reads, keeps its metadata exemption for commands that run alone, checks the string given to `eval`, refuses `echo`, `printf` and `print` of secret-named variables, refuses environment dumps (`ps` environment flags, `/proc/<pid>/environ`, `launchctl getenv`, `$HISTFILE`), and refuses `git credential` and the password-manager and secret-store CLIs.
- Fixes after review: the startup-file search no longer takes quadratic time on repeated newlines, an exemption cannot begin inside a quoted argument, `wc` is no longer exempt, shell tracing and verbose modes are refused, `safe-tool has-key` checks the default file like a named one, reads assignments the way the shell does (several per `export` line, comments, empty values) and answers `unknown` for a file it cannot read completely, and global IPv6 addresses with a dotted IPv4 tail are withheld.
- The startup-file rule now covers `.login`, the zsh, bash and fish config folders, oh-my-zsh custom files, the system-wide `/etc` startup files, more history files (`.zhistory`, fish history, `.irb_history`, `.viminfo` and others), and refuses `history` and `fc`. `source` still works on any startup file or config folder but never on a history file.
- Fixes after review of the screenshot extras: a page's file download can no longer reach the real download folder, the browser hook checks every nested request so an extra key or a renamed batch cannot hide a screenshot and refuses zero, negative and NaN scales, web-shot stops the browser on a termination signal, treats a truncated capture as a failure, refuses link-local and cloud metadata addresses, and writes its output only through a file it still owns.
- Fixes after review of the startup-file rule: `source` of a path that climbs out with `..`, uses a brace or glob, or also names a history file is refused; `setopt xtrace`, `bash -o xtrace` and `-o verbose` are refused; the slow patterns are linear and a glob word is only expanded when it can be a startup path, so ordinary code with many brackets and braces is no longer refused; `ls /etc/profile` works; startup folders are caught without a trailing slash and quote, backslash and percent-escape tricks are undone; more history locations and `/private/etc` are covered; a recursive search from the home folder and a `find` name pattern that could match a startup file are refused; the metadata exemption accepts only system folders as a command prefix; and `safe-tool has-key` reads chains, `+=` and `unset` in order.
- Fixes after a second review of the screenshot extras: `web-shot` refuses host spellings the browser rewrites before it connects (percent escapes, full-width digits, other dots, a backslash, a trailing dot) and the Alibaba and AWS IPv6 metadata addresses, `sim-shot` cleans up on a termination signal like `web-shot`, a second signal cannot interrupt that cleanup, a pipe put on the reserved output path is refused instead of blocking, a write error such as a full disk is a clear message, and the browser hook message states the real scale limits.
- Fixes after a second review of the startup-file rule: the check now has a 3 second budget that ends in a refusal, because a slow check was killed by the host and let the command through; glob words too long to expand, brace ranges (`{z..z}`), escaped quotes, comments, backslash-newline and `$''` inside a name, a closing quote taken for an opening one, a function or alias standing in for `ls` or `source`, globs in other folders, `dotglob` and `GLOBIGNORE`, `find` from the home folder without a name pattern, recursive searches written as `-d recurse`, `../..`, `rg -uu`, with no folder or from `~/.config`, and more trace channels (`dash -x`, `SHELLOPTS`, `shopt -so`, a `DEBUG` trap) no longer get past it; `bash build.sh --verbose`, `find src -name '*login*' | head`, `grep -rn "/Users" src/` and `jq '.login'` are no longer refused; `ps aux -e`, `kubectl get pods,secrets`, `vault print`, here-strings and unquoted here-documents of secret variables, `/proc/self/../self/environ` and `jq -n env` are refused; `safe-tool has-key` joins continued lines, reads `A=$(cmd args)`, reports an unreadable file as `unknown` and accepts a link only when it still leads to a file named like a startup file; every startup-file refusal shows the startup-file message.
- `git show <rev>:<path>` is no longer refused: it prints a file's content, not a commit header, so it cannot show an author. A revision with braces, the `:/text` search form, a bare revision, or a mix of those with a file still count as showing a commit.
- A here-document whose command only reads text from it (`cat`, `tee`, `grep`, `diff`, `jq` without `-f`, and `gh`, as a bare name or a system path, nothing piped on its line) no longer has its body checked as a list of shell commands, so an odd apostrophe, a line that reads like a command (`Report status of the build`) or a mention of a key or startup file in a quoted heredoc no longer blocks writing a brief or a pull request body. This holds only while the rest of the command is plain simple commands: a group, `if`, `case` or loop, a function or alias, `$'..'`, `${..}` other than a plain name, arithmetic, a backtick or a process substitution keeps every line on the ordinary checks, as does an unterminated marker or more than 16 here-documents. An unquoted body also needs to hold no `$(`, backtick or `${`. A heredoc inside `$(...)` counts as text only as the `--body`, `--title` or `--notes` of `gh pr`, `gh issue` or `gh release`. Bodies that a shell or interpreter runs, that are piped, put in a process substitution or passed to `eval` or `bash -c` are still checked.
- Output that shows an SSH login banner (the Ubuntu message of the day, `System information as of`, `IPv4 address for eth0:`, `Last login: ... from`, the known-hosts notice, `Connection to <host> closed`, a failed `ssh: connect to host`), an address behind a label (`inet`, `IP address:`, `public ip`) or the answer of an address lookup service (`curl ifconfig.me`) is now withheld, so a login to a machine on a public address no longer shows its name and address. `AGENT_SAFEGUARDS_SHOW_ADDRESSES=1` turns it off with the private-address rule.
- `safe-tool remote-readonly '<command>'` and `safe-tool redact`: the checker and the output filter for a wrapper around a machine reached through an ssh alias. The checker accepts one pipeline of read commands and refuses writes, redirects, chains, substitutions, endless follows and credential paths; the filter makes addresses, hosts, URLs and `user@host` placeholders and withholds output that holds a secret or a login banner. `systemctl status` and `pm2 status` are no longer refused as a generic `status` command.
- delete-guard now sees through scripts and remote machines. It reads a script (`bash file`, `./file`, `source file`, a `.sh` on the path) before it runs unless Git tracks it unchanged, and applies its rules to what is inside, including functions and loops; it understands `gio trash` and `gio remove` and the `name() {` function header; and a delete on another machine (after `ssh`, an `ssh_*` alias, a name in `AGENT_SAFEGUARDS_REMOTE_COMMANDS`, or a wrapper that vets its deletes) must be a literal `~/...` or `/...` path strictly inside `~/ci` or `/tmp` (`AGENT_SAFEGUARDS_REMOTE_DELETE_ROOTS`), with no `..`, variable, glob or substitution. `delete-guard check-remote '<command>'` runs that rule for a wrapper, so a path a script computed (`ci/..`) is judged after it is expanded.
- Fixes after an independent review of delete-guard: the check has a 3 second budget that ends in a refusal; a script is read without ever waiting on a pipe, and is trusted only when its bytes equal the file in the last commit (Git's `assume-unchanged` and `skip-worktree` flags no longer make an edited script look reviewed); a script launched with quotes, `exec`, `env`, `timeout`, `sudo -u`, `nice`, a relative `dir/script`, `bash -O opt file` or `sh < file` is followed; a function written `f(){ ...; }` or `f ( ) {` shows the command inside; a quoted `cat <<'EOF'` only prints its text; a relative wrapper is the file of the folder the command runs in, and a wrapper vets its deletes only through a line that runs the check; `ssh -tp 22 host` and `mosh --ssh ssh host` no longer hide the command; a quoted or escaped `~` is not a home folder; `find -exec rm` and `rsync --remove-source-files` check their own operands; and `delete-guard remote-preflight` prints a script that makes the machine resolve each permanent delete target and refuse one that a link leads out of the allowed folders.
- Fixes after an independent review of the heredoc rule, the banner rules and the remote checker: a double-quoted delimiter is read with the shell's quote removal and an empty quoted delimiter is accepted; the placeholder word the guard uses cannot be written by the command; `jq --run-tests` is not a data reader; forbidden options are refused when begun, attached or bundled (`--out=`, `-s20000101`, `-us`, `-qf`), `date` with a numeric operand, `free -s`, `journalctl --setup-keys` and `--update-catalog` are refused, `docker top` is not allowed, escaped and split path names are checked as the remote shell reads them, and `uniq FILE`, `docker compose -f x.yml logs` and `systemctl -n 20 status` are no longer refused; `redact` takes an IPv6 address with a dotted tail whole, replaces a long URL to its end, and withholds output over 1 MiB instead of cutting it; and `Connection reset by <host> port 22` is withheld.
- delete-guard and the Trash: sending a file to the Trash is allowed (also on a remote machine, for any literal `~/...` or `/...` path that is not the home folder, a folder directly in it, a mount point or a system folder), and emptying a Trash or deleting inside one is refused. The refused commands are `trash-empty`, `trash-rm`, `trash -e` and `-s`, `--empty`, `gio trash --empty`, `gvfs-trash --empty`, `ktrash --empty`, `kioclient rm trash:/...`, `hadoop fs -expunge`, any `-skipTrash`, the Finder's empty through `osascript`, and `Clear-RecycleBin` or `rd` on `$Recycle.Bin`; a delete (`rm`, `unlink`, `rmdir`, `find -delete`, `rsync --delete`, `gio remove`, `gvfs-rm`, `kioclient rm`) is refused when its target is a Trash folder or inside one (`~/.Trash`, `~/.local/share/Trash`, `$XDG_DATA_HOME/Trash`, `.Trash`, `.Trashes`, `.Trash-<uid>`, `$Recycle.Bin`, `RECYCLER`, `#recycle`, `@Recycle`, `.recycle`, `files_trashbin`, `.trashed-*`, `trash:`), also behind a link and on a remote machine. Moving a Trash, or a folder that holds one, into the Trash is refused. `gio remove` is now treated as the permanent delete it is, and `unlink` and `rmdir` follow the `rm` rules.
- Fixes after the second Codex reviews: a vetted wrapper must run the checker as a command (an `echo`, a string, an assignment, a comment or a here-document line no longer counts) and is read for deletes of its own; `env -C` and `sudo -D` read the script of the folder they move to; `find -exec` and `xargs` check the command they run like a typed one (behind `sudo` and `env`, and the Trash tools); `file:` locations are read as paths and other places are refused for permanent deletes; the macOS spellings of `/etc` and `/var` are protected and `/etc` scripts are never opened; `unlink old.log` and `rmdir files` reach the checks; `kioclient --noninteractive remove` is seen; globs and braces that name a Trash, a Trash behind a link, and a folder with a Trash directly inside are refused; `~"/ci"`-style quoting of the tilde prefix is refused on a remote machine; `find -L`, `-follow` and (remote) `-H` do not delete; `sh < 'file'` is read; a deeply nested hook payload is denied by both tools instead of crashing; `osascript`, PowerShell and `cmd` text that only names the Trash commands is allowed; `trash-put --trash-dir DIR` takes DIR as a folder.
- Fixes in safe-tool after the second Codex reviews: the word that stands for the marker of a here-document is a character the command does not contain, a continued delimiter (`<<"E\<newline>ND"`) is read like the shell, `find -- DIR -delete`, `uniq -- FILE -out`, `ps ax eww`, `journalctl --cursor-file`, `/etc/./shadow`, `/etc//shadow` and `docker stats --no-stream --no-stream=false` are refused, an attached option value (`journalctl -ufoo.service`) is not a bundle of options, refusals never repeat what the caller typed, whole URLs are replaced whatever the case or brackets, and the identity-label pattern is linear on padding.
- Fixes after the third Codex reviews: a glob's matches meet the full delete or Trash rules, the bound on matches and on the folder scan refuses instead of letting the rest through, `**` and zero-padded ranges are expanded the way the shell does, folders that hold a Trash must hold a folder (or an Android trashed file) and a folder that cannot be listed is refused; a path built from a matched name must stay in its folder, `xargs` refuses a `find` or `rsync` that deletes, wrappers inside wrappers move step by step, every file read with `<` is read as a script, the remote preflight resolves a folder that is entered (trailing slash, `find` start, `rsync` destination) itself; `osascript`, PowerShell and `cmd` text that mentions the Trash or the Recycle Bin is refused; `kioclient move remove trash:/` is a move; `find -exec gio info` does not delete; `-L` as a name or as an option of the command find runs is not a find option.
- Fixes in safe-tool after the third Codex reviews: a `--` that the option before it may take as its value is refused, `ps` is read with Linux and macOS option arity (`ps e1`, `ps -C -E`, `--date-format`), the plain form of a path is checked against the general sensitive-path rules, a refusal shows only a plain word, `docker stats --format '--no-stream'` is not a flag, any URL scheme is redacted, and `systemctl -H`, `journalctl -M` and docker's `-H`, `-c`, `--context` and `--config` are refused.
- Fixes after the fourth Codex reviews: find's expression is read by role and arity (a `-name -exec` value hides nothing, `-fprintf` takes two values, BSD `-f` and `-files0-from` are starting folders), a path built from a matched name is refused for a delete or a send, `xargs` refuses any delete or send, keeps its wrapper's directory and never takes a `find` or `rsync` delete, one wrapper changes directory once (its last option) and nested wrappers compose, the input of a shell is the descriptor-0 `<` or `<>` redirection of that shell (or of its group), the glob reader is the guard's own so a folder that cannot be listed or `[^x]` cannot hide a match, brace ranges of any length and step padding are followed, and the preflight resolves the folder of a file that `rsync` removes.
- Fixes in safe-tool after the fourth Codex reviews: `ps` options that take a value follow the target (a remote check is Linux) and a value that begins with a dash is read as options, an unquoted brace list is refused in a remote command, a `--` after an option that takes a value is refused for systemctl too and not after a flag that takes none, docker's `-H` and `-c` are found inside a bundle, and URL schemes of any length are replaced.
- Fixes after the fifth Codex reviews: the standard input of a shell is traced through descriptors in order (`00<`, `0<&3`, `<&9-`, ASCII digits only) and through the groups around it, `find -exec` and `xargs -a` children inherit the input, an escaped `\;` is a word and no longer cuts a command in two, a `find` or `rsync` that deletes cannot run under `find -exec` with the match as its root, `+` ends a `find -exec` command only after `{}`, `-Bnewer` and the other reference-file predicates take their value, `**/` with a trailing slash walks every folder and a trailing slash keeps only folders, named classes such as `[[:lower:]]` are expanded, and a folder whose type cannot be read is refused.
- Fixes in safe-tool after the fifth Codex reviews: `ps -oargs eww` is refused and `ps -oetime` is not (the letters after the first option that takes a value are its value on Linux), unquoted brace lists are found through inner braces and quotes and a comment is not read as a list, and a flag, an abbreviation of a flag or an option that takes its value only attached (`sort --check`, `--sta`, `systemctl --no-ask-password`) is not taken for an option that swallows `--`.
- Fixes after the sixth Codex reviews: the shell-input tracing of the fifth round is replaced by a rule that cannot be pointed at the wrong file (every file the line opens for reading is read when a shell reads its input), opened in the folder of the calling shell and not of a wrapper; quoted punctuation (`env -u '|'`) is a word like escaped punctuation; a script named by a glob or brace list is read for each file; `xargs` options are read letter by letter (`-aFILE`, `-ra FILE`); named glob classes take non-ASCII names; a trailing-slash glob refuses when the type of an entry cannot be read; and the glob matcher is a two-pointer loop, so many stars cannot exhaust the time budget.
- Fixes in safe-tool after the sixth Codex reviews: only a format option (`o`, `O`) keeps the rest of its word as its value in `ps`, so `ps -saxeww` is refused and `ps -oetime` allowed on both systems, accepted abbreviations of systemctl's long options are resolved before the subcommand is chosen (an option that cannot be read is refused), and a `#` in the middle of a word is not a comment.
- Fixes after the seventh Codex reviews: a script is read as written as well as through its pattern, a file opened for a shell's input keeps its folder through wrappers before `find` and `xargs` and through `sh -c`, `eval`, substitutions and scripts, shell option bundles (`-eo pipefail`) take their value, negated named classes keep the non-ASCII names they may match and the space classes take non-ASCII whitespace, and every lookup of a glob entry that fails (existence, type) is a refusal.
- Fixes in safe-tool after the seventh Codex reviews: `systemctl -P` takes its value, `user@host` takes the whole run of labels, and an attached `ps -C` command name is a filter on Linux and not an environment option.
- Optional RTK enforcement: the `require_rtk` plugin setting on Claude Code, or `AGENT_SAFEGUARDS_REQUIRE_RTK` on any host, denies commands that `rtk rewrite` would change. `safe-tool status rtk` reports readiness and whether it is on.
- Plugin for Claude Code and Codex with a fail-closed launcher.
- Skills `command-guards` and `setup-agent-safeguards`.
- Optional Codex rule files under `extras/codex-rules/`.
- Optional simulator screenshot extras for Claude Code on macOS under `extras/simulator-screenshots/`: `sim-shot` saves a shrunk simulator screenshot as a new file and prints its path, and a hook holds the simulator control tool's crashing `screenshot` action for the user.
- Optional website screenshot extras under `extras/web-screenshots/`: `web-shot` saves an `http` or `https` page as a new PNG within fixed limits (1568 pixels, 1 MB) and prints its path, and a Claude Code hook refuses in-app browser and Chrome extension screenshots that do not ask for a scale of 0.5 or lower. The simulator extras share the same limits through `lib/agent_safeguards/screenshot.py`.
- Message catalog in `locales/en.json`.
- Settings through `AGENT_SAFEGUARDS_*` environment variables.
